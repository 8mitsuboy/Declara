# ADR-001: タスク生成に Cognito、API Gateway、Lambda を採用する

## ステータス
- Accepted

## 背景
- 既存実装では、Flutter クライアントが外部 AI API を直接呼び出す前提になっていた。
- クライアントに API キーを持たせる構成は、配布物からの抽出リスクが高い。
- 今後は認証、認可、使用量制御、ログ取得、レスポンス整形をサーバ側で扱いたい。

## 決定
- 本番のタスク生成 API は `Cognito + API Gateway + Lambda` の構成で提供する。
- Flutter クライアントは Cognito で認証されたユーザーのトークンを用いて API Gateway を呼ぶ。
- Lambda が外部 AI API との通信、プロンプト構築、レスポンス整形を担当する。
- クライアントには AI ベンダー固有の API キーやレスポンス構造を露出させない。

## 影響
- セキュリティ上の責務をクライアントからサーバ側へ移せる。
- 認証付きユーザーのみに AI 機能を開放できる。
- クライアントと AI ベンダーの結合を弱められる。
- その代わり、インフラ構築とサーバ運用の責務が増える。

## 検討した代替案
- Flutter から直接外部 AI API を呼ぶ
  - 実装は単純だが、本番運用のリスクが高い。
- 公開 Lambda URL を直接叩く
  - 初期構築は簡単だが、認証・認可の扱いが弱くなりやすい。

## 今後の対応
- API レスポンス契約をアプリ専用の形に定義する。
- Terraform で認証・API・実行基盤を管理する。
- `ClaudeAiService` の扱いをローカル検証専用に整理する。
