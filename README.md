# Declara

宣言するだけで、AIがタスクを生成してくれるタスク管理アプリ。

## エレベータピッチ

「引っ越したい」「晩御飯を作りたい」「水道代を払いたい」——日常には後回しにしがちなことが溢れている。

先延ばしの原因は怠惰ではなく、**何をすればいいかわからない**こと。何をすればいいかわからない → 考えるのが面倒 → でもやらなきゃいけないから落ち込む → さらに動けなくなる。この悪循環の起点は「中身がブラックボックスであること」にある。

Declaraは**宣言するだけでタスクを自動生成するAIタスク管理アプリ**。「引っ越したい」と入力するだけで、AIが具体的な行動を洗い出し、ブラックボックスを開封する。あとはひとつずつ消していくだけ。

## コンセプト

Declaraは**宣言的プログラミング**の思想をタスク管理に適用したアプリ。

- **ユーザーはWhatだけ宣言する。HowはAIが解決する。**
- 壮大な目標管理ではなく、**日常の「やりたい」「やらなきゃ」を片付ける**ためのツール
- 入力の負担を極限まで減らし、「宣言する」だけで行動に移れる状態をつくる

### なぜ「〜したい」が宣言的なのか

「引っ越したい」は意味的に「引っ越した状態になりたい」と同じ。つまり**理想の状態の宣言**である。Reactで `<Button>` と書くとき開発者が「理想の状態を定義している」と意識しないのと同じように、ユーザーも宣言していることを意識しない。自然な入力が、そのまま宣言になる。

この等式が成り立つのは、扱う宣言が日常レベルで具体的だから。「幸せになりたい」のような高い抽象度では「〜したい」と「理想の状態」の間にギャップが生まれる。日常の後回しにしがちなことに絞ることで、コンセプトとUXが一貫する。

## 主な機能（MVP）

- **宣言入力**: 「〜したい」「〜しなきゃ」を自由記述で入力
- **AIタスク生成**: Claude APIが3〜7個の具体的なタスクを生成
- **進捗管理**: タスクの完了/未完了切り替え・進捗表示
- **永続化**: タスク状態はローカルDBに保存され、アプリ再起動後も保持
- **完了アニメーション**: タスク完了時の視覚的フィードバック

## ドメインモデル

```
Declaration（宣言）
├── id: String
├── title: String        // 「〜したい」「〜しなきゃ」
├── done: bool
└── tasks: List<Task>

Task（タスク）
├── id: String
├── declarationId: String
├── title: String        // 具体的な行動
├── done: bool
└── sortOrder: int
```

## アーキテクチャ

```
lib/
├── domain/        # ドメインモデル（外部依存なし）
├── repository/    # リポジトリインターフェース
├── data/          # リポジトリ実装、DB定義、外部サービス
├── pages/         # UI（ページ単位でフォルダ分け）
└── providers.dart # DIコンテナ（Riverpod）
```

- **状態管理**: Riverpod
- **ローカルDB**: Drift (SQLite)
- **バックエンド**: Supabase
- **AI生成**: Claude API
